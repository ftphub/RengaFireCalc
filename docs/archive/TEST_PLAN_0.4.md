# FireCalc 0.4 — приёмочные испытания

**Статус:** разработка/исходники; компиляция и работа с Renga API 2.50 в Windows требуют проверки. Не использовать для выпуска проектной документации без верификации инженера.

## Предварительная проверка
1. Сохранить работающую v0.3.1 и копию Renga `.rnp`.
2. В Windows открыть **Developer PowerShell for Visual Studio 2022** и выполнить `./BUILD_AND_DEPLOY.ps1` (без установки); ознакомиться с `FireCalc_build_log.txt`, сохранить собранный ZIP.
3. Если всё корректно, закрыть Renga и выполнить `./BUILD_AND_DEPLOY.ps1 -Install` (с правами на запись в Program Files). Скрипт создаст резервную копию прежней папки.
4. Открыть Renga и убедиться, что заголовок `0.4.0`, а окно на 1280×720 прокручивается.

## Регрессия v0.3.1
- Вода/ПО: окрасочный — 71,28 / 2,328 м³; ремонтный — 335,52 м³ по воде без сухотрубов / 1,740 м³ ПО. Сравнить с двумя экспортами ЭФЭР и отметить расхождения с PDF.
- Гидравлика примеров: 21,423 и 23,754 м потерь по трассе (с оговорками об участках).
- Трубы: 11 объектов, объём ~0,13605473 м³ на имеющейся демонстрационной модели; Dвн из стиля, длина из количества.
- Запись свойств только в копию модели, сравнить значение при повторном открытии проекта.
- Экспорт Excel запасов и гидравлики, проверить единицы измерения.

## Новая вкладка «Связность / маршруты»
1. Нажать «Проверить маршруты Renga». Зафиксировать количество Route, связных компонент, пропусков и предупреждений.
2. Если Route не обнаружены — это допустимо, **не подменять** геометрию догадками о соединениях.
3. Если есть маршрутные связи: выбрать по отображённым ID начальный и конечный объекты; «Подставить найденные трубы в гидравлику». Проверить порядок выбранных труб и отсутствие галочек на соседних ветвях. Для нескольких путей/колец функция должна отказать.
4. Если компонент без циклов и с одним источником, указать ID источника и `ID_потребителя=Q` для **всех** конечных потребителей (например `1201=40;1202=40`), нажать «Распределить расходы по дереву». Проверить суммарный расход в источнике и расходы отдельных Route. Неполные расходы должны блокироваться.
5. Выбрать путь от источника к одному потребителю. Проверить, что рассчитанный Q предложен для труб соответствующих Route, а **Кт не подставляется автоматически**.
6. Кт, материалы, местные потери, арматуру и напор потребителя задаёт/проверяет инженер. После проверки — «Рассчитать трассу». Скорость потока отображается, отметка 3 м/с — ориентировочная для диагностики, **не нормативное ограничение**.
7. Проверить «Экспорт связности CSV» в Excel. Таблица содержит RouteId, точки подключения, стиль системы, PipeIds, Q дерева.

## Ограничения при сдаче заказчику
- Наличие `Route` и `IRouteParams` зависит от того, как смоделирована система; по незавязанным 3D-трубам сеть не восстанавливается.
- Поиск пути — на уровне связей **маршрутных объектов**, не полного графа фитингов/арматуры.
- Алгоритм расходов работает только для полностью описанного **дерева**, одного источника, с заданными расходами всех конечных потребителей. Не решает кольцевые сети и не рассчитывает давление по ветвям автоматически.
- Нет нормативно верифицированного автоматического справочника Кт для PPR/ВЧШГ, насосных характеристик, расчёта распыла/покрытия, модели арматуры, или автоматической спецификации.
- Облако не используется, Excel не обязателен для экспорта XLSX/CSV.
