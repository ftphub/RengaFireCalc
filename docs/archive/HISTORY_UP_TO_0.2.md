# Renga FireCalc v0.2.0 — экспериментальный гидравлический маршрут

**База:** FireCalc v0.1.4, проверенная пользователем в Renga 9.3. Новая часть v0.2 не собрана и не протестирована в Windows/Renga; требует испытаний.

**Демо-предупреждение:** контрольные группы участков ЭФЭР подобраны по итоговой сумме линейных потерь из PDF, их фактическая непрерывность не подтверждена геометрией объекта.

**Новое:** вкладка «Гидравлика / маршрут», ручной выбор последовательных участков, ввод Q и Кт, расчёт потерь, два примера ЭФЭР с исключением соседних ветвей, экспорт XLSX. Пользователь должен вручную определить диктующую трассу — это НЕ автоматический решатель сети.

**Формула:** `ΔP [МПа] = Q² × L / (100 × Кт)` согласно РУП.Т, стр. 21–22. Коэффициенты из документа нельзя автоматически применять к произвольному материалу трубы.

**Как проверить:** Visual Studio 2022 → Release / x64 → сборка → запуск `FireCalc.Tests` → скопировать содержимое `_build/FireCalc` в отдельную папку `Plugins/FireCalc` (обязательно сохранить резервную копию версии v0.1.4) → в окне открыть «Гидравлика / маршрут» и проверить примеры. См. `docs/HYDRAULICS_0.2.md` и `docs/PLUGINS_REVIEW.md`.

**Безопасность:** никаких сторонних DLL из Plugins.zip не добавлено; данные оттуда использовались только для изучения имен API-подходов. Без сетевых подключений.

# Renga FireCalc v0.1.4 — исследовательский прототип для ЭФЭР

**Статус:** v0.1.3 успешно загружена в Renga 9.3 21.10.2026, расчёты и экспорт XLSX проверены пользователем. Обнаружено: длины всех 10 труб читаются, но диаметр отсутствует из-за обращения к параметрам экземпляра, а не к параметрам его стиля. В v0.1.4 исправлено чтение Dвн через `PipeStyleId` и `Project.PipeStyles.GetById(styleId)`; сборка и тест в Renga **ещё не подтверждены**. Не применять расчёт в рабочей документации без инженерной проверки.

**Исправление v0.1.4 (SDK 2.50):** `PipeInsideDiameter` читается у стиля трубы (через параметр `PipeStyleId` экземпляра), при необходимости используется исходное значение экземпляра; добавлена колонка «Источник Dвн», повышена точность отображения маленьких объёмов до 8 знаков. По IFC-тесту ЭФЭР: 10 труб, геометрический объём **0,009862241136 м³**, для демонстрации, без привязки к гидравлической системе. **Для v0.1.4 требуется пересборка DLL и полная замена плагина в папке Plugins.**

**Исправление v0.1.3:** дескриптор приведён к структуре реально работающего Renga Server Switcher (из присланного пользователем RAR): добавлено поле Copyright, версия в формате `0.1.3.0`, RequiredAPIVersion `2.50`, Vendor `kartashov_ma`. Код C# и DLL не изменены. Быстрая инструкция: [`docs/FIX_0.1.3.md`](FIX_0.1.3.md).

**Исправление v0.1.2:** в `FireCalc.Plugin/FireCalc.rndesc` версия `<Version>0.1.0</Version>` заменена на `<Version>0.1</Version>`. Согласно документации SDK 9.3 допустимы форматы `x.x` или `x.x.x.x`, но не `x.x.x`. DLL/код плагина не изменены; повторная сборка не нужна, если уже успешно собрана v0.1.1.

**Исправление v0.1.1:** добавлена директива `using System.IO;` для типов `FileStream`, `FileMode`, `FileAccess` и `StreamWriter` (ошибки CS0246/CS0103). Остальной функционал не менялся.
Прототип ориентирован на **Renga 9.3 / SDK API 2.50** (плагин Net8, .NET 8, WPF, x64).
Не используйте результаты для выпуска рабочей документации без инженерной проверки.

## Что уже реализовано в коде

1. Панельная кнопка `FireCalc · ЭФЭР` и WPF окно с русским интерфейсом.
2. Локальный расчёт запасов воды, пенообразователя по точным формулам переданного Excel (не требуется Office и интернет).
3. Два предварительно заполненных демонстрационных случая из PDF `РУП.Т`: окрасочный и ремонтные цеха.
4. Диагностическое чтение объектов типа `Renga.EntityTypes.Pipe`, количественной длины `NominalLength` и параметра `PipeInsideDiameter`.
5. Геометрический объём трубы при наличии обеих величин; отображение недостающих сведений.
6. Ручное, подтверждаемое пользователем включение полного набора найденных труб в **объём сухотруба** (не Wтр).
7. Выгрузка результатов, исходных данных и труб в настоящий `.xlsx` из трёх листов без установки Excel.
8. Отдельная кнопка, **только с подтверждением**, записывающая объём каждой корректно прочитанной трубы в пользовательское числовое свойство Renga `FireCalc: объём участка трубы, м³`.
9. Консольный тестовый проект C# `FireCalc.Tests` без зависимостей от Renga.

## Как собрать у себя (Windows)

Требуется Visual Studio 2022 c поддержкой .NET 8, .NET Desktop/WPF, MSBuild и компонентами COM, Renga 9.3 x64. SDK Renga API 2.50 приложен **только в виде двух необходимых файлов**, которые пользователь ранее передал.

1. Распаковать архив целиком в папку без ограничений доступа, лучше `C:\Work\RengaFireCalc\`.
2. Открыть **`FireCalc.sln`** в Visual Studio 2022.
3. Выбрать конфигурацию **Release** и платформу **x64**.
4. Проверить ссылки `sdk\RengaCOMAPI.tlb` и `sdk\Renga.NET8.PluginUtility.dll`.
5. Собрать решение `Сборка → Собрать решение` (`Ctrl+Shift+B`). COMReference требует **MSBuild Visual Studio под Windows**, а не Linux.
6. Либо запустить **`build_and_test.ps1`** из Developer PowerShell for VS 2022; сначала пройдут тесты чистого расчётного ядра.
7. Открыть `\_build\FireCalc\` — ожидаются `Renga.FireCalc.dll`, `FireCalc.Core.dll`, `FireCalc.rndesc`, `Renga.NET8.PluginUtility.dll` и файлы межъязыковой обёртки Renga (если созданы MSBuild).
8. Создать папку `<папка установленной Renga>\Plugins\FireCalc\`. Скопировать туда **всё** из `\_build\FireCalc\`. Имя файла дескриптора должно быть `FireCalc.rndesc` — как имя папки (правило SDK).
9. Перезапустить Renga 9.3, открыть новый или существующий проект и нажать **FireCalc · ЭФЭР** в главной панели.
10. Нажать «Пример: окрасочный», затем «Рассчитать» и «Экспорт XLSX». **Не проверяйте кнопку записи свойств на единственном экземпляре проекта.**

Допустимо сразу запустить форму на пустой модели: для расчёта запасов наличие BIM модели не требуется. Для испытаний извлечения геометрии необходимо создать трубопроводы средствами инженерных систем Renga.

## Важно: чего v0.1 НЕ делает

- **Нет автоматического гидравлического расчёта сети** — только изолированная проверочная формула линейных потерь в ядре, не задействованная в UI.
- Нет восстановления направления потока, ветвей, колец, расчётных участков; нет выбора трассы по отдельной системе.
- Нет автоматического определения, какие трубы относятся к `Wтр`; это поле всегда вводит инженер.
- Нет автоматического создания спецификации Renga и произвольной записи в ячейки таблиц.
- Нет готовой библиотеки 200 изделий ЭФЭР и модуля кабельных трасс.
- Результаты геометрических объёмов не включают автоматически фитинги, клапаны, коллекторы, баки и реальное заполнение.
- Единицы `PipeInsideDiameter` и наличие `NominalLength` на конкретных трубах нуждаются в проверке в установленной Renga. Если значение отсутствует, оно не угадывается.
- Нет гарантии совместимости исходников с иной версией Renga или SDK.
- 21.10.2026 пользователь успешно собрал все три проекта v0.1.1 (3/3). При старте Renga журнал `AecApp.log` зафиксировал неправильный формат `Version` в `FireCalc.rndesc`, поэтому плагин не отображался. После этого Renga сообщила об отсутствующем Copyright; исправлено в v0.1.3. Загрузка самой DLL ещё не подтверждена.

## Состав архива

- `FireCalc.Core` — независимые расчёты, валидация входов, модели труб.
- `FireCalc.Plugin` — Renga API, WPF, выгрузка в XLSX, чтение/запись свойств.
- `FireCalc.Tests` — консольные тесты, два кейса ЭФЭР, проверка гидравлической формулы.
- `sdk` — `RengaCOMAPI.tlb` и `Renga.NET8.PluginUtility.dll` из предоставленного SDK.
- `docs/VALIDATION.md` — детальная карта формул и выявленные расхождения.
- `build_and_test.ps1` — Windows-скрипт сборки.

Источники: `Расчет запаса воды и ПО(1).XLSX` (Лист1, формулы L6/L8/L9/L16/L18/L20/L22/L23/L26/L27), `РУП.Т(1).PDF` (стр. 21–22 — гидравлические расчёты и запасы), `93 RengaSDK(2).zip` (Net8PluginWithWPF, ModelObjects, ModelObjectQuantities, PropertiesAndParameters).

SDK-файлы поставлены пользователем и сохраняют авторские права Renga Software LLC.
