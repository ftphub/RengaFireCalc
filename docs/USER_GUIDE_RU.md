# Руководство пользователя FireCalc v0.5.1

**Назначение:** диагностический и расчётный помощник для Renga 9.3, не автоматический проектировщик пожаротушения.

## Запасы воды и пенообразователя

1. Откройте вкладку **«Запасы воды и ПО»**.
2. Введите длительность тушения/охлаждения, расходы, концентрацию ПО, запасы труб и ёмкость бака; либо загрузите демонстрационный пример.
3. Нажмите **«Рассчитать»** и посмотрите составляющие воды и ПО, проверку бака.
4. Экспортируйте `.xlsx` при необходимости.

**Важно:** показатель `Wтр` относится к расчётной подсистеме ПО и **не равен** суммарному объёму всех труб или сухотрубов.

## Трубы / Renga

1. Нажмите **«Обновить трубы»**.
2. Проверьте ID, длину `L`, внутренний диаметр `Dвн` и объём каждой трубы.
3. В таблице появятся объём в м³ и литрах, статус и источник диаметра.
4. Для передачи общего объёма в поле сухотруба используйте кнопку только после проверки состава конкретной системы.
5. Запись объёмов в свойства Renga выполняйте **только на копии проекта**; затем самостоятельно настройте спецификацию Renga для использования пользовательского свойства.

## Гидравлика / трасса

1. Загрузите пример ЭФЭР для проверки интерфейса либо трубы из текущей BIM-модели.
2. Отметьте **только последовательные участки одной подтверждённой трассы**, не все трубы проекта.
3. Введите `Q, л/с` и коэффициент `Кт` для каждого участка по подтверждённой методике.
4. Задайте местные потери, сопротивления оборудования, напор потребителя и разность отметок.
5. Подтвердите исходные данные инженером, нажмите **«Рассчитать трассу»**.
6. Сверьте скорость, потери и итог; при необходимости экспортируйте XLSX.

Если Q и Кт пустые, расчёт будет заблокирован. Значения из примеров стальных труб ЭФЭР нельзя без обоснования переносить на PPR/ВЧШГ.

## Связность / маршруты

1. Нажмите **«Проверить маршруты Renga»**.
2. Таблица покажет ID маршрута, начальный и конечный объект, стиль системы, число и ID труб.
3. Нажмите **«Прочитать порты оборудования»**, чтобы увидеть связь отдельных портов насосов и фитингов с маршрутами.
4. Для работы с ID выделите строку и используйте **«Копировать ID»**, **«От → начало»**, **«К → конец»**, **«Объект → источник»** — вручную искать ID необязательно.
5. Для сценария насосов можно добавить ID выбранных насосов из таблицы; поле допускает список ID. Однако сценарий только описывает режим, не рассчитывает насосы.

**Особенность текущей версии:** маршрутная диагностика может показать **две компоненты** для физически связанной сети из-за связей через насосы и фитинги. Данные портов необходимо интерпретировать отдельно; нельзя автоматически считать их гидравлической проходимостью.

### Поиск пути

Укажите ID начала и конца, нажмите «Подставить найденные трубы в гидравлику». Функция работает только при однозначном пути в считанном графе; сложные сети и насосы могут приводить к ошибке/блокировке.

### Расходы по дереву

Укажите единственный источник и расходы всех конечных потребителей в формате `ID=Q;ID=Q`, где Q в л/с. Функция ограничена деревом без колец, с подтверждёнными расходами всех потребителей. Если исходные данные неполны, запуск блокируется.

## Подсказки и формулы

Наведите курсор на название параметра или заголовок таблицы. На вкладке **«Подсказки и формулы»** можно искать обозначение и смотреть определения и расчётные зависимости. Hover-подсказки не заменяют инженерную методику.

## Протокол

На вкладке протокола смотрите информацию о расчётах, сканировании BIM и предупреждениях. При обращении к разработчику сохраняйте текст ошибки, версию Renga/FireCalc и шаг воспроизведения, не выкладывая конфиденциальные файлы в публичные Issues.
