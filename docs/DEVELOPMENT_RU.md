# Разработка и архитектура

## Структура исходников

```text
FireCalc.Core/      Чистые формулы, топология, расчёты, описание насосных режимов
FireCalc.Plugin/    WPF UI, Renga API/COM, чтение объектов, экспорт, подсказки
FireCalc.Tests/     Независимые консольные контрольные тесты расчётного ядра
sdk/                Локальные SDK файлы (в Git не попадают)
docs/               Инструкции, схемы, исторические заметки
BUILD_AND_DEPLOY.ps1 Автоматическая Windows-сборка и установка
```

## Сборка

`FireCalc.sln` рассчитан на Windows/Visual Studio с поддержкой COMFileReference и `.NET 8 WPF`. TLB импортируется из `sdk/RengaCOMAPI.tlb`; утилита Renga `.NET8.PluginUtility.dll` подключается как локальная ссылка. **Не заменяйте их DLL сторонних плагинов**.

Запуск независимых тестов:

```powershell
dotnet run --project .\FireCalc.Tests\FireCalc.Tests.csproj -c Release
```

GitHub Actions запускает только Core-тесты, не DLL плагина (SDK и Windows Renga в CI отсутствуют). Зелёный CI не равнозначен подтверждению запуска в Renga или инженерной точности.

## Принципы безопасности расчётов

- Нет молчаливой подстановки отсутствующих Q/Кт и автоматического использования демопараметров.
- Не суммировать потери разных ветвей как одной диктующей трассы.
- Деревья/пути допускаются только при однозначной топологии.
- Различать геометрическую связь портов и физическую гидравлическую проходимость насосов/арматуры.
- Не изменять рабочую BIM-модель без явного действия пользователя.
- Итоги должны содержать ограничения и предупреждения о неполной методике.

## Технический долг / следующий рубеж

Подтверждение связи между `Route` через фланцы, тройники и насосы требует тестов в Renga. Для построения физической сети нужны направление потока, состояние арматуры, условие работы каждого насоса, кривая Q–H и назначение портов.

## Права

Авторский код принадлежит `kartashov_ma`; лицензия на использование сторонними лицами отдельно не предоставлена. Любая публикация клиентских материалов требует разрешений.
